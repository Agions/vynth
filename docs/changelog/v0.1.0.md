# Zeno v0.1.0 发布说明

> 统一发布 · 版本 `0.1.0` · 单二进制 `dist/zeno`（实测 60.51 MiB）

本次发布合并 v0.1.0（初版骨架）/ v0.2.0（MVP 闭环）/ v0.2.1（错误码 6 位化 + demo 移除 + 模型回滚 + DeepSeek V4 thinking）三段历史到单一 `v0.1.0` 版本。GitHub tag `v0.1.0` 接管同名历史 tag。

## 一句话定位

**Zeno 是你 terminal 里的代码合成器**——纯 TypeScript 编写、以单个 Bun 二进制（`dist/zeno`，约 60 MiB）零依赖分发，把自然语言目标「合成」成代码。面向在 shell 工作流里想把一句话变成可运行代码的开发者：无需离开终端、无需搭脚手架，无头（`-g`）或交互（TUI）两种形态直接使用。

## 核心功能清单

- **无头 Agent 模式**：`./dist/zeno -g "<目标>"` 触发 agent 循环，结果流式直写 stdout；无需 TTY，可在管道 / CI 中使用。
- **OpenAI 兼容 LLM（含 DeepSeek V4 thinking 模式）**：`OpenAiProvider` 走 SSE 流式，逐 token 解析 + `tool_calls` + `reasoning_content`（DeepSeek V4 thinking 字段）；工具调用轮次 `reasoning_content` 原样回传 API，符合 DeepSeek V4 规范。
- **6 位错误码体系（VC-XXXXXX）**：所有错误字符串自动带 `[VC-XXXXXX]` 前缀，可被 grep / 日志聚合 / 监控告警按码字符串直接定位；旧字符串族名（`config`/`llm`/...）由 `fromLegacy()` 兼容映射。
- **插件系统**：`zeno -g "<目标>" -p <path>` 动态加载本地 `.ts/.js` 插件，经 `activate(reg)` 注册自定义工具，扩展 agent 能力。
- **单二进制分发**：`bun build --compile` 产出单一可执行文件，无 node_modules、无外部 wasm、无运行时依赖（仅需 Bun 构建环境）。
- **内置工具 + 沙箱守卫**：`read_file` / `write_file`（路径受 cwd 越界守卫 + symlink 二次校验约束，F10 对抗 X3）；`run_shell` 受 `ZENO_NET='0'` 阻断联网。
- **双模式 + 主题**：`plan`（先规划）/`vibe`（边聊边写），Catppuccin `mocha` / `latte` 主题。
- **非 TTY 守卫**：非交互终端下运行 TUI 时退出码 `2` 并提示改用无头模式。

## 快速开始

### 1. 环境要求与构建

```bash
# 需要 Bun >= 1.1
bun install
bun run compile          # → 产出 dist/zeno（实测 60.51 MiB）
```

### 2. 接入真实 LLM（**ZENO_API_KEY 为必填项**）

```bash
export ZENO_API_KEY="sk-..."                            # 必填
export ZENO_MODEL="deepseek-v4-pro"                     # 默认值（与冻结裁决 X1/X2 一致）
export ZENO_LLM_BASE_URL="https://api.deepseek.com/v1"  # 默认值（OpenAI 兼容）
./dist/zeno -g '给当前目录写一份 README.md'
```

> v0.1.0 起 demo 模式（`EchoProvider`）**已移除**——`createProvider()` 在 `apiKey` 为空时抛 `LlmError`（错误码 `[VC-020099]`），不再静默 fallback。请先配置 API Key。

### 3. 加载插件

```bash
./dist/zeno -g '用 hello 工具向世界问好' -p packages/plugins/examples/hello-plugin.ts
```

插件入口需 `export const pluginName` 与 `export function activate(reg)`。

### 环境变量

| 变量 | 作用 | 默认 |
|------|------|------|
| `ZENO_API_KEY` | LLM key（**必填**） | 无（空 → 抛 `[VC-020099]`） |
| `ZENO_MODEL` | 模型名 | `deepseek-v4-pro` |
| `ZENO_LLM_BASE_URL` | OpenAI 兼容端点 | `https://api.deepseek.com/v1` |
| `ZENO_MODE` | `plan` \| `vibe` | `vibe` |
| `ZENO_THEME` | `mocha` \| `latte` | `mocha` |
| `ZENO_NET` | 沙箱网络开关（`'0'` = 禁网，尽力而为） | 开启 |
| `ZENO_DATA_DIR` | 数据目录 | `~/.zeno` |

### 明确不在范围内（Out，本版不做）

- **MCP 接入**：`@zeno/mcp` 的 `McpClient` 已就绪，但**尚未接入 CLI** agent 工具集，本版不暴露 MCP 工具。
- **TUI 内插件加载**：插件加载目前仅支持**无头模式**；交互式 TUI 暂不支持运行时加载插件。
- **配置文件**：配置仅经环境变量注入，**不读取任何 `config.toml` / 配置文件**。
- **预编译发行包**：本版需从源码 `bun build --compile` 自编译，不提供多平台预编译二进制下载。
- **插件签名 / 市场 / 自动更新**：无插件签名验证、无插件市场、无自动更新机制。
- **联网硬隔离**：本版不提供进程级硬网络隔离；`run_shell` 联网现受 `ZENO_NET='0'` 网关阻断，但仍为软网关、非硬安全边界。

## ⚠ 信任边界（务必阅读）

> **Zeno 的插件系统会执行任意代码。**

当使用 `-p <path>` 加载插件时，Zeno 通过动态 `import()` 直接加载并执行文件中的代码（`activate(reg)` 在加载时即运行），**插件代码与 Zeno 本体运行在同一运行时、拥有同等权限**：

- 可读取 / 修改你文件系统上的**任意**文件（不受内置工具 cwd 沙箱约束）；
- 可读取**所有环境变量**，包括 `ZENO_API_KEY` 等敏感凭据；
- 可发起**任意网络请求**、执行**任意命令**。

**Zeno 不对插件代码做沙箱隔离或权限限制。** 因此：

- ✅ **仅从你完全信任的来源加载插件**（自己的代码、团队审计过的代码）。
- ❌ **不要加载来源不明、未经审查的插件**——恶意插件可窃取凭据、破坏文件、远程控制。
- 🔒 在共享 / CI 环境中使用 `-p` 前，确认插件路径与内容可信。

内置 `read_file` / `write_file` 受 cwd 越界守卫约束；`run_shell` 以**宿主权限**运行（`sh -c`，仅设置工作目录、无命令 / 文件系统隔离）；**插件注册的自定义工具同样不受沙箱约束**。工具的能力边界 = 你的进程能力边界。

## 安全模型摘要

本版 Zeno **不提供进程 / 网络 / 文件系统的硬隔离**，其安全模型建立在「用户以自身宿主权限运行」这一前提上：

- **信任模型 = 宿主权限**：agent 循环、内置工具与插件均以你的用户权限运行；Zeno 不隔离、也不降低这些权限。
- **`run_shell` 非隔离**：直接以 `sh -c` 在宿主执行命令，仅设置工作目录，无命令 / 文件系统沙箱。
- **插件以宿主完整权限运行**：`-p` 经动态 `import()` 加载的代码可读取任意文件、读取所有环境变量（含 `ZENO_API_KEY`）、发起任意网络请求、执行任意命令——仅加载可信来源。
- **`ZENO_API_KEY` 发往所配置的 LLM 端点**：请求地址由 `ZENO_LLM_BASE_URL` 决定，并受端点校验保护——**已拒绝向远程明文 `http` 端点发送密钥**（localhost 放行以保留本地调试），非默认端点会打印告警。

## 升级与回滚

Zeno 为单二进制分发，升级即覆盖：

```bash
# 升级前保留上一版本快照（推荐）
cp dist/zeno dist/zeno.prev

# 重新构建并覆盖
bun run compile        # 覆盖 dist/zeno

# 若需回滚，将快照覆盖回去即可
cp dist/zeno.prev dist/zeno
```

- 二进制为单文件，无数据库 / 配置迁移；回滚只需恢复可执行文件本身。
- 数据目录 `~/.zeno`（`ZENO_DATA_DIR` 可改）跨版本兼容，回滚一般不会影响。
- 多版本并存：可将不同版本重命名为 `zeno-0.1.0` / `zeno-prev` 等放入 `PATH`。

## F12 · MCP CLI 接入（v0.1.0 新增）

Zeno 现在可通过 `-s/--mcp` 接入任意 stdio MCP server，将其暴露的工具并入 agent 工具集，与内置工具 / 插件共用同一套沙箱与审计链路。

- **协议锁定**：stdio JSON-RPC **2024-11-05**（见实施开发计划 §2.3 / 风险 U-05）。
- **用法**：`zeno -g "<目标>" -s "bun run packages/mcp/examples/echo-server.ts"`；`-s` 可重复以接入多个 server。
- **接入流程**：启动子进程 → `initialize` → `tools/list` → 将每个 MCP 工具转换为 `ToolDef`（`name` / `description` / `parameters` 由 JSON Schema 映射，`integer`→`number`）→ 注册进 `ToolRegistry` → agent 调用时经 `tools/call` 转发。
- **错误处理**：server 异常退出会令挂起请求失败；`tools/call` 错误以 `ToolResult.ok=false` 返回，不抛出；连接失败抛 `McpError`（6 位码 `VC-06xxxx`）。
- **示例 server**：`packages/mcp/examples/echo-server.ts` 暴露一个 `mcp_echo` 工具，供联调与测试。
- **验证**：`packages/mcp` 单测（协议转换 + echo server 端到端）、`@zeno/harness` e2e（MCP 工具并入 agent 工具集并被调用、`-s` 参数契约）。
## F13 · TUI 内插件（v0.1.0 新增）

交互式 TUI 现在支持加载本地插件，并通过信任确认门禁接入信任模型（替代「仅无头模式可加载插件」）。

- **用法**：`zeno -p packages/plugins/examples/hello-plugin.ts` 启动 TUI，进入交互界面后会弹出信任确认；`y`/`yes` 才加载，`n`/回车拒绝（插件代码不会被执行）。
- **信任模型联动**：插件在本进程内执行任意代码，拥有与 Zeno 同等的文件系统 / 网络 / 命令权限。确认回调 **在 `import` 之前** 返回 `true` 才真正 `import` + `activate`，故门禁在任意代码执行前生效。
- **无头模式不变**：`-g ... -p <路径>` 中 `-p` 即显式授权，直接加载、不做交互确认（适配脚本 / 管道）。
- **统一实现**：`packages/plugins` 新增 `loadPluginsWithTrust(paths, reg, confirm)`，返回 `{ loaded, declined, errors }`；TUI 用 TTY `rl.question` 确认回调，无头模式用 `async () => true`。`runHeadless` 与 `startTui` 共用同一加载路径。
- **验证**：`packages/plugins` 新增 `trust.test.ts`（确认通过 / 拒绝 / 加载失败 / 逐插件独立确认四例）。

## F14 · 配置合规层（v0.1.0 新增）

新增配置合规层：可选配置文件（ADR-0003 受控扩展）+ 5 维审计落盘。

- **可选配置文件**：`loadConfig` 现读取 `ZENO_CONFIG_FILE` 或 `<ZENO_DATA_DIR>/config.json`（**可选、opt-in**）。合并优先级 `代码 overrides > 环境变量 > 配置文件 > 默认`，环境变量始终最高优先级。
- **安全红线**：配置文件**禁止写入 `apiKey`**（违反抛 `VC-010005`）；非法 JSON / 未知键抛 `VC-010006`。宁可启动失败也不静默接受错误配置。允许的键：`mode` / `model` / `llmBaseUrl` / `theme` / `sandbox.{networkAllowed,cwd}` / `dataDir` / `audit`。
- **5 维审计**：`tool_exec` / `file_access` / `network_egress` / `config_change` / `plugin_load`。落盘 append-only JSONL `<ZENO_DATA_DIR>/audit.log`（零依赖，符合 ADR-0003 单二进制约束，不引入原生模块）。
- **审计单例**：`packages/core` 新增 `audit.ts`（`initAudit` / `audit` / `resetAudit`）。CLI 启动后按 `config.audit` 初始化；钩子点（engine agent-loop / sandbox / plugins loader）直接 `audit().record(...)`，避免在函数签名中透传。
- **默认关闭**，启用：`ZENO_AUDIT=1` 或配置文件 `audit:true`。启用后高危操作 100% 策略留痕。
- **错误码**：新增 `VC-010005`(CONFIG_FILE_SECRET) / `VC-010006`(CONFIG_FILE_INVALID)。
- **验证**：`packages/core` 新增 `audit.test.ts`（JSONL 写入 / 禁用 no-op / 未初始化安全）+ `config.test.ts`（合并 / apiKey 拒绝 / 非法 schema / audit 标志）；`packages/engine` 新增 `tool_exec` 审计端到端测试。`bun test packages` 92 pass 0 fail；体积门禁 60.52MB<61MB。
