## 1. 工程规矩（Conventions）

### 1.1 仓库、构建与包边界
- **Monorepo**：pnpm workspace + turbo。`packages/*` 为 `@vynth/*` 库，`apps/cli` 为二进制入口。
- **包 ↔ 模块映射**（禁止越界调用，跨域仅经 `@vynth/core` 共享契约）：
  | 模块 | 包 | 职责 |
  |---|---|---|
  | M1 会话接入 | `apps/cli` | parseArgs / printHelp / runHeadless / startTui 路由 |
  | M2 Agent 引擎 | `@vynth/engine` | agent loop、编排 |
  | M3 LLM 客户端 | `@vynth/engine` | SSE、Provider 适配 |
  | M4 工具与沙箱 | `@vynth/engine` + `@vynth/sandbox` | read/write/shell、safeResolve |
  | M5 插件系统 | `@vynth/plugins` | 无头加载（MVP）、TUI 内加载（F13） |
  | M6 配置与基座 | `@vynth/core` | config/types/events/logger/errors |
  | M7 MCP 客户端 | `@vynth/mcp`（完整版） | stdio JSON-RPC 2024-11-05 |
- **横切契约**（仅放 `@vynth/core`，全局唯一）：`VynthConfig` / `StreamEvent`（token/tool/done 跨层协议）/ `ToolDef`+`ToolResult`（Published Language）/ `VynthError`（6 位错误码体系）/ `Emitter`（进程内事件总线）。
- **单二进制**：`bun build --compile` 产出 `dist/vynth`；CI 内做体积门禁（见 §1.4）。

### 1.2 编码与质量
- TypeScript `strict`；格式化与 lint 统一用 **biome**（不混用 prettier/eslint）。
- 所有外部错误须映射为 `VynthError` 子类（config/llm/tool/sandbox/mcp/plugin），禁止裸 throw。
- 日志走 `@vynth/core` logger + OpenTelemetry，结构化 JSON，必含 `traceId`（多租户语境下另含 `tenantId`，本期单用户可省略）。
- 不引入额外大依赖（如 winston/pino/RxJS）：体积与零依赖是硬约束。

### 1.3 分支与提交
- 分支：`main`（稳定）/ `release/x.y` / `dev` / `feat-<Fx>`（如 `feat-f10-sandbox`）。
- 提交：Conventional Commits，必须关联功能或模块，例如 `feat(F5): add sandbox-guarded shell tool`、`fix(X3): harden safeResolve against symlink`。
- PR：至少 1 人审批；CI 全绿（含密钥扫描与 harness e2e）；关联对应 F#/M#。

### 1.4 CI/CD 流水线（8 阶段，来自部署设计 §4）
> 任一阶段失败即阻断合并/发布。

1. **install**：pnpm i（锁版本，零偶发升级）
2. **lint/typecheck**：biome + `tsc --noEmit`
3. **build packages**：turbo 构建 `@vynth/*`
4. **compile 单二进制**：`bun build --compile` → `dist/vynth`
5. **test**：`@vynth/harness` e2e（核心会话、无头、退出码、越界守卫）
6. **安全扫描**：SCA（npm/bun audit）+ SAST + **密钥硬编码扫描（红线：命中即失败）**
7. **签名 / notarize**：代码签名（macOS notarization）
8. **发布**：渠道 beta / stable（npm / brew / GitHub Releases）

- **体积门禁**：阶段 4 后校验 `dist/vynth` 体积，MVP ≤ 61MB、完整版 ≤ 40MB，超限失败。
- **回滚**：重新下载旧版 / `brew rollback` / `npm dist-tag`，二进制快照机制。

### 1.5 测试策略
- 单测：vitest，覆盖 `@vynth/core` 契约、sandbox `safeResolve`、LLM SSE 聚合。
- e2e：`@vynth/harness`，覆盖 US-1~US-8 关键路径（含真实 Key 会话、无头插件、退出码、越界被拦）。
- 性能基线（CI 监控）：冷启动 P95 ≤ 150ms；单二进制体积门禁。
- **禁止**：为赶工砍 e2e 覆盖；MVP 骨架不得引入完整版无法继承的临时架构。

### 1.6 发布与版本
- semver；渠道 `beta`（预发布）→ `stable`（生产）。
- 变更需回写架构文档（`delivery/` 对应章节）与本文档，保持可追溯。

### 1.7 安全红线（来自安全设计，MVP 即生效）
- **密钥不硬编码**：`VYNTH_API_KEY` 仅经 env 或 OS keychain 注入；CI 密钥扫描红线。
- **提示注入**：系统提示完整性保护、工具结果沙箱化、危险操作二次确认、注入检测。
- **命令注入**：shell 工具禁用动态拼接，白名单参数化数组。
- **路径穿越**：`safeResolve` 规范化 + symlink 校验（对抗 X3）。
- **SSRF**：工具出站仅 `VYNTH_NET` 白名单（LLM Provider + 可选 MCP），禁访问内网。
- **审计（完整版强化）**：工具执行 / 文件访问 / 网络出站 / 配置变更 / 插件加载 5 维审计日志，保留 ≥1 年。

### 1.8 文档与追踪
- 每个 F 有验收标准（回溯 UserStory §5）；改动落地后回写 `delivery/` 对应章节。
- 本计划与 `delivery/G6_交付汇总.md` 冲突时，以 G6 汇总裁决为准。

## 2. 实施开发计划（Roadmap）

### 2.1 阶段总览
| 阶段 | 周期 | 范围 | 退出标准 |
|---|---|---|---|
| **Phase A · MVP** | W1–W6 | F1–F11（P0） | 单二进制 beta 可用；核心会话 + 无头管道 + 退出码语义；体积 ≤61MB；真实 LLM 接入 |
| **Phase B · 完整版** | W7–W14 | F12–F15 | DAU/管道稳定 30 天；高危操作 100% 策略留痕；体积 ≤40MB；OS 级硬隔离 |

> 架构约束：MVP 骨架必须是完整版的子集，不允许上线后推倒重来；MVP 中 Mock/简化的能力（MCP 未接、无 OS 沙箱）在完整版有明确替换计划（F12 / F15）。

### 2.2 Phase A · MVP 迭代拆解（W1–W6）

**Sprint 1（W1）· 基座 + CLI 骨架**
- 范围：M6（`@vynth/core`：types/config/events/logger/errors）+ M1（F1 单二进制启动、F11 退出码/帮助）。
- 产出：可 `bun build --compile` 的单二进制；`--version` / `--help` 正确；退出码 0/2/非0 语义；CI 阶段 1–4 跑通。
- 验收：二进制可运行；无 Key 不崩；体积基线记录。

**Sprint 2（W2）· Agent 引擎 + LLM**
- 范围：M2（F4 agent loop，maxSteps=8）+ M3（F6 OpenAI 兼容 SSE、F7 默认 DeepSeek 对齐）+ F8 真实 LLM 接入。
- 产出：有 Key 跑通基础会话；无 Key 时抛出 LlmError（要求显式配置 VYNTH_API_KEY）。
- 验收：流式 token 直写不卡顿（定性）；冷启动 P95 ≤ 150ms 基线测量。

**Sprint 3（W3）· 内置工具 + 沙箱守卫**
- 范围：M4（F5 read/write/shell 经 sandbox）+ F10（safeResolve + symlink 校验，对抗 X3）。
- 产出：工具经 sandbox 执行；越界/符号链接逃逸被拦截。
- 验收：越界用例 100% 拦截；工具结果可审计。

**Sprint 4（W4）· 插件无头接入**
- 范围：M5（F9 `-p/--plugin` 无头加载并激活）。
- 产出：无头模式加载插件、退出码语义明确、可脚本化管道。
- 验收：US-7 无头插件路径 e2e 通过。

**Sprint 5（W5）· TUI 双模式**
- 范围：M? TUI（F2 自研 ANSI 渲染 + 逃生舱、F3 Plan/Vibe 双模式 + mocha/latte 主题）。
- 产出：TUI 流式渲染、双模式切换、主题切换。
- 验收：高频 token 直写无全树重渲染；逃生舱可降级到纯文本。
- 说明：TUI 与 S2–S4 模块解耦，可并行排期以压缩 W2–W5。

**Sprint 6（W6）· 集成 + 发布**
- 范围：全链路集成 + `@vynth/harness` e2e + 单二进制编译 + 体积优化（≤61MB）+ 签名 + beta 发布。
- 产出：MVP beta 渠道发布；退出码语义、真实 Key 会话、越界守卫、无头插件全绿。
- 验收：US-1~US-8 e2e 通过；体积门禁通过；G4 已裁决的「不承诺 token SLA」在文档/测试阈值落地（仅冷启动 P95 硬指标）。

### 2.3 Phase B · 完整版拆解（W7–W14）

| 功能 | 模块 | 关键工作 | 依赖 |
|---|---|---|---|
| **F12 MCP CLI 接入** | M7 `@vynth/mcp` | `McpClient` 并入 agent 工具集；锁定 stdio JSON-RPC **2024-11-05** | MVP 骨架稳定 |
| **F13 TUI 内插件** | M5 扩展 | TUI 加载插件 + 信任模型联动（替代仅无头） | F12 工具集就绪 |
| **F14 配置合规层** | 新增配置中心 | 可选配置文件 + 审计（O3，ADR-0003 扩展） | 安全审计框架 |
| **F15 OS 级硬隔离** | 沙箱增强 | bubblewrap(Linux)/seatbelt(macOS) + `VYNTH_NET` 硬网关（方案 A：MVP 软→完整版硬） | 跨平台 e2e |

- 退出标准：高危操作 100% 策略留痕；单二进制体积 ≤40MB；DAU/管道稳定 30 天。

### 2.4 依赖与排序依据
- **M6 基座先行**（S1），所有模块依赖其契约。
- **TUI（S5）可并行**于 S2–S4（不同模块、无强耦合），用于压缩周期。
- **单二进制编译（S6）最后**，需所有包就绪。
- **完整版依赖 MVP 骨架稳定**：F12/F13 在 MVP 模块上扩展；F15 替换 MVP 软隔离为硬隔离，不推翻会话/工具链路。

### 2.5 关键风险与缓解（来自 R-01~R-05、U-02/U-03/U-05）
| 风险 | 说明 | 缓解（已写入架构） |
|---|---|---|
| R-01 沙箱无硬隔离 | MVP 仅软 `VYNTH_NET` | MVP 文档化已知局限 + 提示注入/路径守卫；F15 完整版 OS 级硬隔离 |
| U-02 单二进制体积 | 当前 ≤61MB，目标 ≤40MB | CI 体积门禁 + 依赖审计，禁止大依赖 |
| U-03 OS 沙箱跨平台 | bubblewrap/seatbelt 差异 | 分平台实现 + e2e；MVP 不阻塞 |
| U-05 MCP 协议版本 | 版本未锁定 | 锁定 stdio JSON-RPC 2024-11-05（F12） |
| R-04 MCP 生态 | 未接入非阻塞 | O1 → F12 完整版 |

### 2.6 度量与验收闸门
- 冷启动 P95 ≤ 150ms（CI 监控）。
- 单二进制体积 ≤ 61MB（MVP）/ ≤ 40MB（完整版）（体积门禁）。
- 退出码语义 0/2/非0（e2e）。
- 真实 Key 会话率 100%（VYNTH_API_KEY 必填，空值报错）。
- `@vynth/harness` e2e 全绿（US-1~US-8）。
- 体积/密钥扫描红线（CI 阶段 6）。
- 完整版：高危操作 100% 策略留痕（5 维审计）。
