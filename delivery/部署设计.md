# AICoding 架构设计 · 部署设计

> 本文档为《AICoding 架构设计》核心产物之一，对应**系统部署设计模版**。
> 上游输入：《系统设计》G4 已通过（vynth 本地优先单二进制 TUI 编程工具）、《高层架构设计》G3 已通过（方案 A：MVP 沙箱推迟至完整版）、《行业调研报告》G2、《项目资料摘要》G1。
> 下游输出：可落地的分发渠道、CI/CD 流水线、本地运行时运维、监控告警、应急回滚等交付物。
> 本文档为 **G5 部署设计**阶段唯一 Owner（platform-architect / 毕落地）产出。

> **部署形态适配说明（本地优先单二进制）**：vynth 是「本地优先单二进制 TUI 编程工具」（类比 Claude Code / OpenCode / Codex CLI）。它不是 SaaS、不是多租户、不是有入站流量的服务器。它用 `bun build --compile` 编译为单个二进制（`dist/vynth`）；是 pnpm-workspace + turbo monorepo 的 `@vynth/*` 包集合；在开发者本机运行，**仅出站**访问 LLM Provider（默认 DeepSeek `https://api.deepseek.com/v1`）走 HTTPS；可选在本机 spawns 子 shell 执行工具；可选经 stdio 连 MCP（F12，尚未合入 CLI）。**产品本身没有数据库、Redis、Kafka、VPC、多 AZ。**
> 因此本模板已把云中心化的章节改造为「本地优先单二进制分发 & 运行时」语境。下列章节保留模板一级/二级骨架，删除不适用的纯云章节（如 VPC/多 AZ/多 Region 灾备），把剩余结构用本地二进制内容重框——每张云专属表格均重框为本地等价内容并填实，无空表、无裸写「N/A」。

> 云模板的 dev/int/uat/prod 4 环境在本项目重释为「**构建环境 + 发布渠道**」四态。隔离策略标注为：本地用户环境 vs CI 沙箱 vs 签名发布。

| 环境 | 用途 | 隔离策略 | 构建 / 产物形态 | 数据 | 网络访问 |
| --- | --- | --- | --- | --- | --- |
| local-dev | 开发者本机自测（`bun run apps/cli/src/main.ts`） | 开发者本机隔离（各自 `~/.vynth`），无共享状态 | 源码直跑（未编译单二进制） | 本地 SQLite `~/.vynth/vynth.db` + 模拟 / 真实会话 | 出站 HTTPS（LLM） |

## 3. 部署拓扑与高可用设计

### 3.1 物理拓扑（本地运行时 & 分发拓扑）

#### 3.1.1 物理拓扑图

> 本地单二进制形态：无 DMZ / VPC / 集群。拓扑为「**构建（monorepo CI）→ 分发（渠道）→ 运行（本地进程 spawns 子 shell、出站至 LLM over TLS、可选 MCP stdio）**」三段式。图由 diagrams-generator（graphviz `dot`）生成，PNG + SVG，PingFang SC 字体，已内嵌于 `./pic/部署拓扑图/`。

![Vynth 本地优先单二进制 构建→分发→运行 拓扑图](pic/部署拓扑图/vynth_deploy_topology.png)

#### 3.1.2 拓扑要素清单

| 要素 | 取值 |
| --- | --- |
| 跨 Region 部署 | 否（本地进程，分发渠道为全球 CDN 边缘，但二进制运行于用户本机） |
| 跨 AZ 部署 | 否（无集群） |
| 流量入口路径 | 用户启动二进制（无网络入口）；CI 拉取源码构建（入站仅 CI 平台 → runner） |
| 内部调用路径 | 进程内函数调用（StreamEvent / ToolDef 契约）+ 本地 stdio（MCP，完整版） |
| 数据库访问路径 | 本地 SQLite 单文件读写（`~/.vynth/vynth.db`） |
| 出站路径 | 仅 LLM Provider HTTPS（默认 `api.deepseek.com:443`） |

### 3.2 流量与网络链路（连通视图）

#### 3.2.1 出站入口链路（本地进程 → LLM Provider HTTPS）

| 组件 (R-xx) | 协议 - 端口 | TLS 终结 | 作用 |
| --- | --- | --- | --- |
| 本地进程 `vynth` → LLM Provider (R-N-001) | HTTPS (OpenAI 兼容 SSE) - 443 | 由 LLM Provider 云端终结；本系统仅发起 HTTPS，`assertSafeEndpoint` 拒绝明文 http（非 localhost） | 流式补全 / tool_calls 聚合 |
| 本地进程 → MCP 子进程 (R-N-002，完整版 F12) | 本地 stdio JSON-RPC（非网络） | N/A（本地管道） | 扩展工具集 |

#### 3.2.2 内部互联链路（本地 IPC）

| 项 | 说明 |
| --- | --- |
| 服务发现 | 进程内模块引用（无注册中心）；禁止硬编码跨进程地址 |
| 服务间协议 | 进程内函数调用 / STDIO JSON-RPC（MCP，完整版） |
| 内部 mTLS | 不适用（进程内 / 本地 stdio） |
| 跨进程调用幂等性 | 工具调用（run_shell 等副作用）须用户确认（Plan 预览 / 完整版权限分级）；透传 traceId |
| TUI ⇄ engine ⇄ tools/sandbox | 进程内 AsyncIterable（StreamEvent）直连，无网络跳 |

#### 3.2.3 跨网络互联（本地进程出站 / 可选 MCP）

| 互联类型 | 通道 | 带宽 | 加密 | 用途 |
| --- | --- | --- | --- | --- |
| 出站 LLM（公网） | HTTPS / 公网 TLS1.2+ | 受 LLM Provider 限速；本地 QPS 上限 10/进程 | TLS（强制 HTTPS） | SSE 流式补全 |
| 跨进程 stdio（MCP，完整版） | 本地子进程管道 | 本地内存带宽 | 本地进程内（非网络） | 工具扩展 |
| 宿主 Shell（本地） | `spawn sh -c` | 本地 | 无（本地进程，受 VYNTH_NET 软开关） | run_shell 工具执行 |
| git / 本地文件 | 本地 fs | 本地磁盘 IO | 无（本地） | 项目读写（sandbox 管控） |

### 3.3 高可用与故障容错

#### 3.3.1 故障域划分（本地单进程语境，4 层）

| 故障域 | 影响范围 | 容错机制 | 预期 RTO |
| --- | --- | --- | --- |
| 单进程崩溃（未捕获异常 → 退出码非 0） | 当前会话 | 退出码非 0 + 保留 `dist/vynth.prev` 快照；用户重启二进制 | ≤ 1min（本地重启） |
| 进程 OOM / 内存超限 | 当前会话 | OOM kill → 退出码非 0；触发崩溃报告 R-O-001 | ≤ 1min（重启） |
| 外部 LLM 不可达 / 超时 | 会话降级 demo / 报错 | BD-02（无 Key → EchoProvider；不可达 → 终止并提示） | 即时（用户重试） |
| 单二进制损坏 / 分发失败 | 无法启动 | 重新下载二进制 / `brew rollback` / npm `dist-tag` 回退；保留 prev 快照 | ≤ 10min（重下 / 回滚） |

> **可用性来源拆分**：
> - 宿主 OS / 磁盘：计算 / 存储由用户 / OS 厂商保障。
> - 本系统自身保障：崩溃恢复（dist/vynth.prev）、fail-fast、优雅退出（SIGTERM/SIGINT → 停止新输入 → 完成在飞 turn → 退出）。
> - 强依赖外部（E-01 LLM）故障策略：demo 降级 / 报错（BD-02），由研发团队保障。

## 4. 部署流程

### 4.1 代码仓库与分支

| 项 | 规范 / 值 | 说明 |
| --- | --- | --- |
| 代码仓库地址 | `github.com/vynth-team/vynth`（示例，以实际仓库地址为准） | monorepo（pnpm workspace + turbo） |
| 分支管理 | `main`（保护分支，须 PR + CI 绿）/ `develop`（集成）/ `release/v*` / `beta/*` | 单一主干 + 发布分支 |
| 合并规范 | PR → review ≥ 1 → CI 全绿（8 阶段）→ squash merge 至 main | 禁止直接 push main |
| 标签规范 | 语义化：`v0.1.0`（stable）、`beta-0.1.0`（beta）、commit short sha 用于产物溯源 | tag 触发发布流水线 |

### 4.2 流水线（CI / CD，8 阶段）

> 核心章节。pnpm + turbo monorepo 流水线，8 阶段：install → lint/typecheck（biome）→ build packages → compile 单二进制（bun）→ test（harness e2e）→ 安全扫描（SCA/SAST + 密钥硬编码扫描）→ 签名/notarize → 发布到渠道（npm/brew/release）。

| 阶段 | 触发条件 | 关键动作 | 失败处理 |
| --- | --- | --- | --- |
| 1. install | push / PR / tag | `bun install`（或 `pnpm install`），缓存 `~/.bun` | 阻断后续 |
| 2. lint/typecheck | install 后 | `biome check .` + `tsc --noEmit`（turbo，全包） | 不达标阻断 |
| 3. build packages | lint 后 | `turbo build`（workspace 包编译，dependsOn `^build`） | 阻断后续 |
| 4. compile 单二进制 | build 后 | `bun build --compile --target=bun --minify apps/cli/src/main.ts --outfile dist/vynth` | 阻断后续 |
| 5. test（harness e2e） | compile 后 | `bun test packages`（e2e.test：流式 token + 工具 + sandbox + plugin + demo） | 阻断后续 |
| 6. 安全扫描 | test 后 | SCA（`bun audit` / `npm audit`）+ SAST（semgrep / biome security）+ **密钥硬编码扫描（gitleaks / trufflehog）** | 高危漏洞 / 密钥命中 **阻断** |
| 7. 签名 / notarize | 扫描通过后 | 生成 `dist/vynth.sha256`；macOS 可选 `codesign` + `notarytool`（需 Apple Developer ID） | 签名失败重试 / 阻断发布 |
| 8. 发布到渠道 | tag（`v*` / `beta-*`）触发 | `npm publish` + 更新 Homebrew tap formula + 上传 GitHub Releases + 可选 CDN 同步；升级前 `cp dist/vynth dist/vynth.prev` | 发布失败回滚至上一 tag |

### 4.3 构建产物与制品管理

| 配置项 | 配置值 / 规则 | 说明 |
| --- | --- | --- |
| 产物类型 | 单二进制可执行文件（`dist/vynth`）+ SHA-256 校验和 + 可选签名 | 无容器镜像 |
| 制品仓库 | GitHub Releases（主）+ npm registry + Homebrew tap（镜像） | 多渠道冗余 |
| 制品命名 | `vynth-0.1.0-darwin-arm64`（命名含版本号 + 平台标识） | 平台区分 |
| 制品保留期 | Releases / npm ≥ 12 个月；`dist/vynth.prev` 随新版本覆盖（仅保留 1 份快照） | prev 为单份滚动快照 |
| 制品溯源 | 二进制内嵌 `git-commit` / `build-time` / `pipeline-id`（构建期注入 `--define` 或版本常量）；`dist/vynth.sha256` 校验和 | 便于反查源码 |
| 签名与校验 | cosign / Apple codesign（macOS notarize）；每次发布校验 SHA-256 | 是否启用 notarize 取决于 Apple Developer 资格 |

### 4.4 配置管理（L1~L4 四层级）

| 层级 | 存储位置 | 适用内容 | 变更生效 | 约束 |
| --- | --- | --- | --- | --- |
| L1 代码内 | 代码仓库（如 `packages/core/src/config.ts`） | 默认值、枚举、常量（DeepSeek 默认端点 / model / 主题） | 重新编译 | 禁止写入环境差异 / 密钥；以代码为准（X1/X2 冻结） |
| L2 配置中心 | 完整版可选配置文件（`~/.vynth/config.*`） | 业务开关、限流阈值、审计开关 | 热更新（监听文件变更） | 变更须幂等（F14，完整版） |

### 4.5 发布策略

#### 4.5.1 发布方式

> 全系统采用「**单二进制覆盖发布 + 快照回滚**」方式（无滚动 / 蓝绿 / 金丝雀概念，因本地无集群）。按渠道区分：

| 模块 / 渠道 | 发布方式 | 说明 |
| --- | --- | --- |
| 单二进制（stable） | 覆盖发布 + prev 快照 | `cp dist/vynth dist/vynth.prev` → 发布新版本；用户 `brew upgrade` / `npm i -g` / 重新下载 |
| 单二进制（beta） | 覆盖发布 + prev 快照 | 内测渠道独立 tag，与 stable 隔离 |
| 配置（L2，完整版） | 热更新 | 监听文件变更，不重启进程 |

#### 4.5.2 发布标准流程

- **首次发布标准流程**：初始化各渠道（npm 作用域包 / brew tap / GitHub Releases）→ 跑通 8 阶段 CI → 打 `v*` tag → 发布 → 验证 `--version` 退出码 0 + `-g` 冒烟退出码 0。
- **常规迭代发布流程**：PR 合入 main → tag `v*` → CI 8 阶段全绿 → 自动发布至 beta → 人工审批 → 晋升 stable。
- **资源变更流程**：无外部资源（本地无 DB / 中间件），变更仅二进制 + 配置；SQLite schema 变更（完整版审计表）须随二进制版本演进，旧版本兼容读取旧表（向前兼容）。

#### 4.5.3 灰度路径与观测窗口

| 批次 | 范围 | 观测窗口 | 放量条件 |
| --- | --- | --- | --- |
| 批次 1：beta 渠道 | 内测用户（团队 + 受邀） | ≥ 3 天 | 崩溃率低于 1%（无 P0 告警） |
| 批次 2：stable 渠道 | 全量公开用户 | ≥ 7 天 | beta 窗口达标后人工审批晋升 |

#### 4.5.4 发布门禁

| 门禁项 | 拦截条件 | 检查时机 |
| --- | --- | --- |
| 单元测试 / e2e 通过率 | 100% | Build / Test 阶段 |
| 类型检查通过 | 0 错误（tsc --noEmit） | Lint/Typecheck 阶段 |
| 集成测试通过率 | 100%（harness e2e） | Test 阶段 |
| 静态扫描严重问题数 | 0（高危）；中危需评审 | Lint 阶段 |
| 安全扫描高危漏洞 | 0（SCA/SAST） | Security Scan 阶段 |
| **密钥硬编码扫描命中** | **0（API Key / 密钥误提交即阻断）** | Security Scan 阶段 |
| 单二进制体积 | ≤ 61MB（MVP 红线，回归即阻断；完整版目标 ≤ 40MB） | Build 后 / Release 前 |
| 人工审批 | 至少 1 名 Owner（@platform） | stable 发布前 |

## 6. 应急与回滚

### 6.1 回滚机制

#### 6.1.1 回滚触发条件

- 发布后崩溃率 > 1%（退出码非 0 占比，本地上报 / CI 冒烟失败）
- 单二进制体积回归 > 61MB（门禁已拦，若漏网则触发）
- P0 告警触发（CI 失败 / LLM 不可达且非 demo）
- 校验和不符（`dist/vynth.sha256` 校验失败 → 下载损坏）

#### 6.1.2 回滚决策人

- P0（CI 失败 / 体积回归 / 严重缺陷）：`@platform` 主值班可独立决定回滚。
- 其他级别：Owner（@engine / @security / @ext）决定。

#### 6.1.3 回滚执行 SOP

| 对象 | 回滚方式 | 预计耗时 | 有损风险 / 数据丢失 |
| --- | --- | --- | --- |
| 应用版本（单二进制） | 重新下载上一版本 / `brew rollback` / npm `dist-tag` 切回 previous / 覆盖 `dist/vynth.prev` → `dist/vynth` | ≤ 5 min | 无（本地进程级，不影响数据） |
| 配置（L2，完整版） | `~/.vynth/config.*` 保留 N 个历史版本，回写上一版 | 小于 1 分钟 | 无 |
| 本地数据（SQLite） | 随用户文件系统；可选 `~/.vynth/backup/` 快照回放 | ≤ 10 min | 理论上无（仅追加写入）；RPO ≤ 5min |

> 升级标准流程（与《系统设计》§4.3.2 对齐）：升级前 `cp dist/vynth dist/vynth.prev`；异常时一行回滚 `cp dist/vynth.prev dist/vynth`；验证 `--version` 退出码 0 + `-g` 冒烟退出码 0。

### 6.2 故障应急 Runbook

#### 6.2.1 Runbook 索引

| Runbook 编号 | 关联告警 | 故障场景 | Owner |
| --- | --- | --- | --- |
| RB-01 | AL-01 | CI 构建 / 发布失败 | `@platform` |
| RB-02 | AL-02 | 单二进制体积回归超限 | `@platform` |
| RB-03 | AL-03 / AL-05 | LLM 不可达 / 高延迟 | `@engine` |
| RB-04 | AL-04 | 沙箱越界 / 网络禁止尝试 | `@security` |

| RB-06 | AL-07 | 插件加载失败率上升 | `@ext` |

#### 6.2.2 Runbook 编写规范

每条 Runbook 按以下结构编写：
- **症状**：触发该 Runbook 的可观测特征（CI 状态 / 告警内容 / 用户反馈）。
- **诊断（按顺序执行）**：定位根因的诊断步骤，明确使用的可观测工具与查询路径。
- **缓解**：分场景的处置动作（与回滚 §6.1、降级、限流、切换等机制衔接）。
- **升级**：缓解未生效的升级条件、升级路径与对外通告机制。

#### 6.2.3 RB-01：CI 构建 / 发布失败

- **症状**：CI 流水线某阶段红（compile / e2e / 安全扫描），或发布渠道上传失败；关联 AL-01。
- **诊断（按顺序执行）**：
  1. 查看 CI run 日志，定位失败阶段（install / lint / build / compile / test / scan / sign / publish）。
  2. 若 test 失败：本地 `bun test packages` 复现，检查 harness e2e 用例。
  3. 若 scan 失败：检查 gitleaks/trufflehog 报告，确认是否误提交密钥（AL-06 联动）。
  4. 若 publish 失败：检查 npm 权限 / brew tap 写入权限 / Release 上传配额。
- **缓解**：
  - 场景 A（test/scan 红）→ 修复代码或依赖，重新 push 触发 CI。
  - 场景 B（publish 失败）→ 手动重发该阶段，或回退 tag 重新发布。
- **升级**：3 次重发仍失败 → 升级 Maintainer，暂停本次发布窗口。

#### 6.2.4 RB-02：单二进制体积回归超限

- **症状**：Build 后体积 > 61MB，发布门禁拦截；关联 AL-02。
- **诊断**：
  1. 对比上一版本体积（`du -h dist/vynth`）。
  2. 检查是否引入大型依赖 / react 残留（R-02 风险）；`bun build --compile --minify` 是否生效。
- **缓解**：清理残留依赖 + tree-shaking；若确须增大，经 Owner 评审放宽门禁（不推荐，目标 ≤ 40MB）。
- **升级**：体积持续膨胀无法压回 → 升级架构组评估外置大依赖。

#### 6.2.5 RB-03：LLM 不可达 / 高延迟

- **症状**：会话中断、SSE 错误率 > 50%、P99 > 2s；关联 AL-03 / AL-05。
- **诊断**：
  1. 检查 `VYNTH_LLM_BASE_URL` 是否为 `https://api.deepseek.com/v1`（冻结默认值）。
  2. `curl -I https://api.deepseek.com/v1` 验证端点可达 + TLS。
  3. 检查 `VYNTH_API_KEY` 是否设置（缺失则走 demo，非故障）。
- **缓解**：
  - 场景 A（端点不可达）→ 终止会话并提示检查网络 / Key（BD-02）；用户重试。
  - 场景 B（高延迟）→ 提示用户切换模型 / 检查网络。
- **升级**：持续 > 30min 不可达 → 升级 @engine，评估 Provider 状态页。

#### 6.2.6 RB-04：沙箱越界 / 网络禁止尝试

- **症状**：`safeResolve` 拒绝越界路径（B040001）/ `VYNTH_NET=off` 拒绝联网（B040002）；关联 AL-04。
- **诊断**：
  1. 查日志 `~/.vynth/logs/` 中 `sandbox.escape` / `sandbox.network` 事件，确认是正常拦截还是误判。
  2. 检查 `cwd` 设置（默认 `process.cwd()`）与 symlink 指向。
- **缓解**：
  - 正常拦截 → 无需动作，记录审计（完整版 `t_tool_call`）。
  - 误判 → 调整 `cwd` 或用户确认路径合法性。
- **升级**：频繁越界尝试（疑似恶意插件 / prompt injection）→ 升级 @security，评估 VYNTH_NET 硬网关（完整版 F15）。

#### 6.2.7 RB-05：密钥硬编码扫描命中

- **症状**：CI 阶段 gitleaks/trufflehog 命中 API Key / 密钥；关联 AL-06。
- **诊断**：查看扫描报告，定位文件 + 行号 + 密钥类型。
- **缓解**：立即从代码中移除密钥 → 轮换该密钥（若已泄露）→ 重新提交（不含密钥）→ 清理 git 历史（filter-repo）。
- **升级**：确认密钥已泄露至公开仓库 → 升级安全组，启动应急响应 + 密钥吊销。

#### 6.2.8 RB-06：插件加载失败率上升

- **症状**：`-p` 插件加载失败率 > 10%；关联 AL-07。
- **诊断**：检查 `packages/plugins` 加载日志，定位失败插件路径 + 错误（PluginError B060001）。
- **缓解**：插件未导出 `pluginName`/`activate` → 退回插件开发者修复；MVP 仅无头模式，不影响主链路。
- **升级**：核心插件大面积失败 → 升级 @ext，评估插件契约兼容性。
